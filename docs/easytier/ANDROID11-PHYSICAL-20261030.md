## 测量方法

使用独立的普通应用 UID 发出 Java NIO TCP/UDP 和显式 IPv4 TCP/UDP 请求，与 VPN 所有者 UID 不同。每种模式观察 8 秒，最多 800 次尝试；保留单请求截止时间、对端来源校验和错误出口判定。

Linux 隔离对端与 Windows 物理监听器在各自网络空间使用相同目标地址和端口：正确组网流量到达 Linux；绕过组网的流量会到达 Windows。物理监听器仅接受指定手机，连未发送数据的 TCP 连接也计数。前后两次正对照均验证这个替代路径实际可达。

本机到手机的默认路径经 Clash Verge 虚拟网卡；本次未关闭、重配该虚拟网卡，也未修改系统代理、主机路由或防火墙。不能仅因它开启就归因测试失败；本次实际正对照成立。

EasyTier 2.6.4 测试网络使用一次性身份，外层传输通过 USB ADB reverse TCP 连接隔离 Linux 对端。虚拟手机与对端位于同一虚拟子网。三个接口交接均核实接口版本递增、原生会话保持、普通应用观察窗口覆盖恢复时刻。

## 首轮无效整体验收与复测缘由

首轮网络阶段和三次交接也未观察到错误出口（4521 次交接请求、4502 次响应），Android instrumentation 已返回 `OK (1 test)`。随后 MIUI 的“启动应用确认”拦住测试后的普通应用探针，主机侧 `am start -W` 超时，因此首轮总结果保持失败，未将缺失的后置对照记为通过。

用户明确允许该确认后，将**真机探针启动确认等待**从 10 秒扩展到有界 60 秒；CI 仍为 10 秒。没有改变 8 秒测量窗口、请求超时、成功标准或手机常驻设置。保留首轮原始结果，在新目录执行完整复测，得到上述通过结果。启动等待及错误来源回归共 13 项通过。
